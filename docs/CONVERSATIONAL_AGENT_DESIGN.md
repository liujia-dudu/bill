# 对话式 Agent 架构

日期：2026-10-16。v0.4.1 已实现对话入口和共享记忆，详细范围与验证边界见 [实现记录](IMPLEMENTATION_STATUS.md)。现有共享资料保留；独立公司查询已停用，历史查询结果仅归档。

## 1. 产品入口

首页改为持续对话界面，支持文字、图片和文件附件。用户说目标，Agent 查找上下文、资料与经验，调用功能完成任务。
开票是第一个业务能力；未来功能复用对话、记忆、任务状态和结果展示，不各自新建一套对话系统。

已确认：尽量纯对话，允许新建多个对话，同一用户的长期资料/偏好共享，每个对话的临时上下文和正在处理的任务独立。
资料与记忆的查看、修改、删除都通过聊天完成，不要求用户跳转独立资料页或记忆管理页。
界面保留会话列表、消息区、输入框和附件上传；资料摘要、进度、截图及审核操作以对话内卡片呈现。
卡片用于准确选择和核对，不另建表单工作台；历史任务从所属对话或用户主动查询中返回。
不添加头像、工作台装饰、演示模块或无操作价值的状态标记。

示例：

1. 用户发二维码图片：“这张帮我开发票。”
2. Agent 检索默认抬头、收票方式、相似任务和匹配流程，检查当前交易是否已有申请。
3. 资料明确且齐全则直接准备；缺项或多个同等可能的抬头时，在对话中简短询问或显示候选。
4. 在同一对话展示进度、填写核对和截图。用户不必先去资料页再返回任务页。
5. 用户说“这次换成个人”，只修改本次任务；说“以后默认个人”，更新长期偏好并简短告知。
6. 用户说“这个邮箱记住，以后用它”，把明确的新偏好和适用范围保存，后续任务自动检索使用。
7. 用户说“你记住了我哪些开票信息”“把公司邮箱改成……”“忘掉这个抬头”，Agent 通过记忆工具读取或修改，随后返回实际变更结果。

当前真实提交禁止规则继续有效。“帮我开发票”执行至填写/回读/截图；用户核对后只记模拟成功。
聊天记忆、截图确认或模型判断都不能自行开启真实提交。

## 2. 对话、记忆、任务分别存储

| 内容           | 用途                                               | 保存规则                                                 |
| -------------- | -------------------------------------------------- | -------------------------------------------------------- |
| 对话消息与附件 | 用户意图、追问、临时更正、结果引用                 | 按 conversationId 持久保存，刷新/重启后继续              |
| 结构化业务资料 | 公司全称、税号、邮箱、个人资料                     | 复用现有 profiles，保存来源/修订；不由摘要代替准确原值   |
| 长期偏好       | 默认抬头、称呼/别名、常用收票方式                  | 用户明确表达的稳定偏好可自动保存，注明作用范围和来源消息 |
| 任务与经历     | 某次使用的资料、处理状态、失败原因、人工反馈、截图 | taskId 关联对话；页面状态和结果由工具确认，保留历史事实  |
| 流程经验       | 页面特征、字段映射、工具轨迹、引擎兼容性           | 自动记录供下次检索参考；未经校验不能直接作为可执行规则   |

第一版记忆至少带类型、主体、内容或资料引用、来源、时间、状态、适用范围和被替代关系。
明确纠正覆盖当前有效偏好，旧记录标为已替代；一次任务选择不自动升级为长期默认。
模型推测可作为待核对候选，不能变成确认税号、默认抬头或用户授权。
网页文字仅是外部证据，不能写成“用户要求”或扩大工具权限。

记忆操作通过受控的查询/保存/更新/遗忘工具执行，不给模型任意文件写入权限。
用户通过聊天查看、修改、删除。记忆工具成功写入后再告知已记住或已修改，不能只口头承诺。
对用户明确给出的稳定资料、默认选择和纠正可自动维护，无需每次要求用户说“记住”，也不逐项重复确认。
一次性的“这次”指令留在当前任务；适用范围或具体主体有歧义才询问，不静默更改其他公司资料。
遗忘后不再检索使用；历史任务证据的删除另行明确处理。
不承诺只保存过就永远能准确记住；检索不到、来源冲突或身份不明时如实询问。

## 3. 执行关系

```text
用户文字 / 图片 / 文件
          |
    对话服务与附件存储
          |
    Harness 主 Agent
      |          |
  记忆检索    业务能力工具
                 |
         开票（含页面企业查询） / 后续功能
                 |
        任务执行器、校验和动作限制
                 |
      结构化结果 -> 同一个对话
```

主 Agent 管理对话与意图，决定需要查哪些资料、使用哪个能力；具体业务模块负责业务约束及副作用。
新能力注册描述、输入输出和可调用工具；只加载当前需要的工具集，不一次暴露全部功能。
第一版继续使用单一主 Agent，不先增加多 Agent 协作、复杂队列或远程插件平台。

执行发票任务前先查当前指令、有效资料/偏好、相关经历与规则，构建本次资料快照。用户并发修改不改写快照；页面查询补入税号时经程序验证，显式更新本任务快照与对应资料修订。
优先级为本次明确指令 > 用户明确默认 > 已确认事实 > 历史经验提示；相互冲突则解释并确认。
流程规则完整匹配时，浏览器执行阶段不调用模型；新页面或步骤变化由 Harness 模型分析并受控执行。
规则按完整域名组织为 `src/adapters/<域名>/flow.json` 与 `policy.json`；通用加载/执行代码在 `src/rules/`，不新增逐站 `fillA()`。每任务运行时读取正式 JSON，空目录、规则新增或删除不要求部署；运行任务保存规则快照并在下一动作前检查变更。域名仅用于索引，资料字段范围、引擎、页面和逐步契约还需唯一匹配。详细结构与当前边界见 [域名规则架构](DYNAMIC_RULES.md)。
业务 Harness 成功填写、回读和截图后由后端导出候选；不能直接发布正式规则或批准审核。填写审核与截图确认、真实提交启用分别记录，当前真实提交仍关闭。旧客如云专用配置与硬编码填写已移除，正式规则集合当前为空。
对话层本身可能需要模型理解“这张用上次公司”，因此不能承诺整轮聊天零模型调用。
保留“对话模型调用”和“业务执行模型调用”的分别统计。

持续会话使用固定 conversationId 与 Harness sessionId 对应，不再每条消息启动一个空白对话。
Harness 会话历史用于续聊，长期记忆由应用业务存储管理；上下文压缩不等于长期记忆。
共享资料/偏好按 userId 保存，每条消息、附件、工具调用和任务均绑定所属 conversationId。
每轮根据当前意图重新检索相关有效记忆，不把其他对话的聊天记录、临时选择、待审核动作或浏览器现场自动拼入当前上下文。
一个对话中的“以后默认用 A”可影响其他对话之后新建的任务，但不改写已经运行的任务快照。
一个对话中的“取消”“继续”“这张票”仅作用于该对话明确关联的任务；跨对话查看/操作历史任务需解析并核对具体任务引用。
历史任务事实和流程经验可以按需检索，不能把历史任务的执行权限、审核状态或临时操作继承给新任务。
空闲可以关闭模型运行时，下一轮恢复会话；不能因为进程关闭就丢失聊天和记忆。
模型恢复不恢复浏览器现场：浏览器按任务状态重新准备、回读和截图，旧确认不能复用。

长任务返回 taskId 后在后台执行，进度和结果通过任务事件更新对话卡片。
用户可继续问进度或纠正资料；修正绑定具体任务，执行前检查任务修订，避免旧任务继续写旧值。
取消先停止新动作再关闭资源，结果不明的真实动作只能查询，不能因续聊重新执行。

## 4. 页面税号查询与会话删除

不再提供站外模型公司搜索工具、候选服务或独立公司查询卡片。企业全名和邮箱明确但税号缺失时允许发起填写。浏览器 Harness 输入公司全名并选择唯一完整名称匹配项；程序从同页购买方税号控件回读，不接受模型给出的税号值。候选税号存在时须和回读一致；候选仅含名称时须验证税号从选择前发生变化，避免残留值误存。18 位信用代码校验位检查和 15/20 位税号格式检查仅验证结构，不替代来源准确性核验。

保存前核对完整公司名称、原资料修订、已有税号是否冲突，保存 company-query.json 和 company-query.png 后才补入资料。共享资料更新会使其他旧截图审核失效；本次任务同步新的资料修订。临时资料仅更新当前任务，不变成长期默认。页面没有查询、多个同名/近似候选、返回值冲突或未知请求被拦截时停止，不绕过提交拦截。

会话列表支持删除；先停止该对话回复与任务，等待资源关闭，再清理 scoped 消息、附件、任务、工具幂等记录、模型会话与任务截图。共享开票资料、偏好保留；用户需另行通过聊天遗忘。取消单独“历史开票记录”入口，新结果以 taskId 引用在所属对话中展示，后台任务记录用于执行状态、核对和截图引用，不再建立第二份结果列表。删除会话后不会被旧迁移再次生成。

## 5. 图片入口

上传图片先保存附件，不立即代表授权执行。用户文字决定是开票、识别还是询问。
二维码通过现有解码器识别；多码、模糊或不支持入口在对话中让用户补充或选择。
主对话已声明 text/image 输入并用 qwen3.8-max 实测，图片缩放后通过 Harness 传给模型。
二维码解析仍用本地解码器。图片可理解不等于模型可可靠识别任意模糊小字或所有证照。

## 6. 现有代码复用与最小新增

保留 SQLite、profiles、二维码工具、页面税号来源核对、浏览器动作限制、任务执行和截图证据。
把当前表单发起任务的 API 封装成 Agent 可调用的业务工具；对话入口可直接选择/管理资料。
修改单次 Harness 包装，支持命名会话、恢复、多轮消息和任务事件回传。

新增 conversations/messages、memories，以及任务与对话/附件的关联；继续使用本地 SQLite 和文件。
先按资料主体、别名、任务和流程特征检索，再在有实际规模/召回需求时补语义索引。
不先引入独立向量数据库，不把全部聊天记录每次塞进模型，也不让对话摘要成为第二份税号资料库。

## 7. 第一版验收

- 连续对话、图片上传、刷新/服务重启后恢复消息和任务结果。
- 发图说开票，自动找到已保存的默认资料；缺项在聊天中补齐，多个候选就地选择。
- 同一用户不同对话共享已确认资料/偏好；“这次用 A”只影响本次，“以后用 A”影响之后的新任务，不改写正在执行的任务。
- 聊天中可查看、修改、删除资料和记忆，无需跳转资料页；工具持久化完成后才反馈成功。
- 同时打开两个对话时，“取消/继续/确认”的任务和附件不串用；跨对话历史查询按具体引用处理。
- 先检索已验证流程和历史经验；完整匹配直接执行，未知页面调用模型；历史过期不冒充当前页面事实。
- 多步填写的进度、截图、错误和审核显示在同一对话中，模拟结果不冒充真实受理。
- 发票执行中允许询问/取消/更正，任务引用不混淆，模型不能代替用户审核。
- 新增另一项能力时复用同一消息和记忆机制，不复制整套前端与 Harness 生命周期代码。

用户已确认：尽量纯对话管理资料和记忆；同一用户跨对话共享资料与偏好，任务上下文各自独立。
v0.4 按此交互和隔离边界实现，尚未覆盖的真实平台/长会话压力等限制以实现记录为准。
