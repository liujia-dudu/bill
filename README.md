# 秒开票

v0.4.5。用于学习 Agent 的本地单用户代码 Demo，由 DeepSeek Harness 驱动，以持续对话为主。
在聊天里保存资料和偏好、发图片开票，进度、截图和确认都留在原对话中。税号通过开票页面自带的企业查询核对后保存。
当前只执行填写测试，不真实提交发票申请。
已验证 pos.mzdpgroup.com 的订单读取、企业联想与税号回读；订单金额为 0 或未加载时停止填写，不进入截图审核。
金额支持只读输入框和行内文本展示；客如云 t2 等订单读取完成后核对页面金额，避免误读默认的 100 元。
已验证 t2 的 normal 引擎填写：已存税号可唯一匹配企业查询结果，同名不带税号的创建项不会阻塞完整匹配；隐藏星号不视为必填，手机号可选时留空。

## 启动

需要 Node.js 24+、Python 3.10+：

```powershell
npm install
python -m pip install -r requirements.txt
npm run browser:install
npm run build
npm start
```

打开 http://127.0.0.1:3180 。开发运行用 npm run dev。
模型和云浏览器配置读取本项目 .env，变量见 [.env.example](.env.example)。
Windows 下 Harness 是后台子进程，不应弹出额外 CLI。当前固定 SDK 的启动点通过 `tools/patch-harness-windows.mjs` 补齐 `windowsHide: true`；安装与 start/dev 前自动应用幂等补丁，版本或代码不匹配时要求重新审核，不修改 SDK 的会话和关闭协议。
作者本机使用百炼业务空间专属接口与 qwen3.8-max；仓库不附带任何账号配置，需在自己的 `.env` 中填写服务地址、模型名称与 Key。Key 不进入前端，导出的 API Key CSV 不进版本控制。
资料目录默认按项目根定位，可用 INVOICE_AGENT_DATA_DIR 覆盖；端口由 INVOICE_AGENT_PORT 设置。

## 在聊天中使用

- “看看我保存了哪些开票资料。”
- “记住我的个人抬头是张三，收票邮箱是……，以后默认使用。”
- “把这家公司的收票邮箱改成……。”
- 企业资料可先保存公司全名和邮箱，税号留空；发来开票入口后在页面查询，名称唯一匹配、页面回读核对后自动补入资料。不再进行独立模型联网税号搜索。
- 上传二维码图片，说“这张帮我开发票。”——先检索已有资料与经验，再开始任务。
- “这次用个人。”——仅对本次任务生效，不改长期默认。
- “忘掉这个抬头”“以后叫我小林”——通过工具实际更新共享资料或记忆。
- “进度怎么样”“取消这张票”“修改后重新准备”——只控制本对话明确关联的任务。

可建立多个对话，同一用户的资料和偏好共享；每个对话的附件、临时选择、任务和审核独立。
历史对话右侧可删除，会停止该对话的回复和任务，并清理消息、附件、任务结果与模型会话；已保存的共享资料和偏好保留。
长期默认变更不改写已经运行的任务快照。“这次”的临时资料用于下一个任务后清除。
截图核对通过后点击任务卡片的“填写正确”，仅记录模拟成功；模型没有代替用户审核的工具。

图片支持 PNG/JPEG，单张最多 10 MB；文本附件支持 TXT/MD/CSV，最多 200 KB。
上传本身不发起开票。发消息后图片经缩放发送给模型理解，二维码地址仍以本地解码结果为准。
不支持 PDF、Word 或任意格式文件解析；跨站验证码、只能提交才能推进的流程仍会停止并说明原因。

## 对话与记忆

- 聊天消息和附件引用持久保存；刷新、服务重启后可以继续。
- 每个对话使用独立 Harness 会话。每轮运行后释放进程，下轮从持久会话恢复。
- 共享资料保持结构化原值，不从摘要还原税号/邮箱；每轮检索当前有效资料和相关偏好。
- 长期偏好、别名和任务经历记录来源及时间；一次选择不默认变成长期偏好。
- 上下文接近上限时使用 Harness 的上下文整理；长期记忆与对话摘要分开。
- 遗忘后不再检索使用相关记忆，并在下一轮重建模型上下文，避免旧模型历史继续引用。历史聊天和任务证据仍可查看，不作为“已擦除所有历史数据”的承诺。
- 开票浏览器执行规则完整匹配时直接复用；未知或变化页面由业务 Harness 调用模型。对话理解与业务执行分别记录模型调用。

规则经验可以跨任务检索，但未经人工审核的轨迹不会自动升级为可执行规则。
正式规则按完整域名组织为 `src/adapters/<域名>/flow.json` 和 `policy.json`，通用执行器运行时读取 JSON；增删改规则无需重启或重新部署。
域名只用于索引，购买方、资料字段范围、引擎、页面及每步契约仍须唯一匹配。当前正式规则集合为空，旧客如云未核验预置规则及专用填写函数已移除，真实页面仍走 Harness。
动态规则详细结构、审核与安全限制见 [域名规则架构](docs/DYNAMIC_RULES.md)。

## 数据与目录

```text
src/
  web/                 聊天界面、资料/任务/截图消息卡片
  server/              对话 API、附件接口、事件推送、配置和启动
  core/chat-service.mjs 对话生命周期、能力调度、资料与记忆工具
  core/attachments.mjs 图片/文本附件、本地二维码解码
  core/runner.mjs      业务任务串行执行、回读、审核、取消
  agent/chat-tools.mjs 主对话 Agent 的能力定义与提示词
  agent/               Harness 运行时、模型配置和浏览器查询/填写工具
  rules/               域名规则加载、结构校验、通用执行和候选导出
  adapters/<域名>/     正式 flow/policy JSON；当前为空，允许目录缺失
  browser/             浏览器连接、观察和禁止提交限制
  storage/             SQLite、消息、记忆、资料及旧数据迁移
tests/                 本地单元/集成测试、聊天端到端测试、显式真实模型测试
tools/                 二维码工具、配置检查、历史只读观察工具
data/
  invoice.sqlite       资料、输入、任务、对话、消息、记忆、工具幂等记录
  uploads/             图片与文本原件
  artifacts/<taskId>/  各步骤截图、字段回读、浏览器轨迹
                       规则执行另存 rule-snapshot.json，记录实际加载副本
  harness/             独立对话/任务的 Harness 历史、逐轮调用与关闭记录
  adapters/candidates/含域名、步骤契约和 flow/policy 的待审核草稿
test-results/          独立测试数据库、截图、验证报告
diagnostics/           专项诊断与迁移备份
```

已有 profiles 保留；不再生成“历史开票记录”对话。仅含迁移任务的旧入口取消，旧任务/证据归档保留；如该入口已有用户聊天则保留并改名。新任务只在所属对话展示。
页面税号查询证据保存在任务目录的 company-query.json / company-query.png，资料记录页面来源、时间和任务引用。删除所属对话会删除任务截图；共享资料中已核对的税号与来源说明仍保留。旧 company-searches 目录仅为历史归档，不再读取或生成。
data/ 是本机普通 SQLite/文件，备份前停止服务并复制 data/。不把该目录作为网页静态资源发布。

旧三页导航、资料弹窗、旧页面写接口、正则候选模块及对应 UI 测试辅助代码已移除。
只读 /api/profiles 和 /api/tasks 保留用于本机诊断；所有产品写操作均走所属对话的消息或卡片动作。
新增业务能力应在主 Agent 能力定义中注册工具，并将处理逻辑放到独立业务模块，复用对话/记忆/任务记录。

## 验证

```powershell
npm test
npm run test:e2e
npm run check:adapters
python -m unittest discover -s tests -p test_decode_qr.py -v
```

普通测试不调用真实模型。UI 端到端使用独立数据库、合成二维码及测试专用对话模型替身，浏览器填写通过测试目录的合成规则 JSON 和生产通用执行器完成；运行前需要完成构建和浏览器安装。
真实二维码原图和案例索引不随仓库分发；依赖 `data/samples/` 的 Node/Python 回归在本机样本缺失时明确跳过。公开合成测试不能替代真实商家填写验收。
显式真实模型检查：

```powershell
npm run test:chat
npm run test:harness
node tests/chat-tax-live.mjs
node tests/chat-qr-live.mjs
```

test:chat 验证资料写入、同会话续聊、跨会话共享、单次覆盖、图片入口、重启恢复、记忆与遗忘。
它仅解码本机测试图并执行已知客户端入口分类，不提交真实发票。
test:harness 用本地合成表单验证真实模型的页面企业查询、税号回读、多步填写和截图审核。
chat-qr-live 使用真实主对话 Harness 验证旧失败二维码附件恢复和任务启动，任务执行器为替身，不打开商家网页。二维码附件先直接解码，再尝试经过一致性校验的固定图案修复；解码升级后旧失败附件可直接重读。

## 当前限制

没有自动真实提交、验证码远程接管或任意网页网络权限。页面没有企业查询、出现验证码、未知接口被拦截、候选有歧义或税号冲突时停止并说明；不自动开放未知请求。页面来源加格式检查不等于工商权威认证，真实平台兼容性仍需逐一测试。
浏览器任务串行执行，对话仍可继续，排队任务最多 20 个；任务修正需要先停止原执行，再重新准备。
模型实际回复可能有差异；精确资料写入、跨对话操作限制、工具权限和审核由程序检查。
当前是本地单用户版本，未提供多账号认证、同步或公网服务。
记忆检索使用结构化资料和关键词，不是无限制语义召回；已接入开票及页面企业查询，尚未加入其他外部业务。

详细设计和证据见 [对话架构](docs/CONVERSATIONAL_AGENT_DESIGN.md) 与 [实现记录](docs/IMPLEMENTATION_STATUS.md)。
