## 1. 当前阶段与资料入口

用户先在“开票资料”页面保存企业/个人抬头、税号、收票邮箱及条件所需的手机号等资料，
再在任务页选择资料。无需在开发对话中提供资料；资料页未实现不作为向用户索要资料的理由。
t2 的 light/normal 填写对照安排在资料页、任务快照和最小填写流程完成之后。

| mode | 当前阶段是否允许 | 行为（待实现） |
| --- | --- | --- |
| read_only | 是 | 观察页面及已有记录，不填值、不接受协议、不提交 |
| dry_run | 是，填写默认模式 | 填写、回读校验、截图，等用户审核后本地反馈模拟成功 |
| execute | 否，后续单独开放 | 通过共用提交控制器办理真实申请 |

模式固定在任务中，适配器、Agent、回放、重试、批量和人工接管均继承。
当前不点击提交/确认开票，不调用申请接口，不用回车或协议动作绕过限制。
无法排除创建申请、锁单或消耗链接的中间动作停在执行前，记录阻塞原因。
必要协议若是进入后续步骤的前提且副作用不明，也不能为了截图继续试点。

资料实际回读一致、已到达所有必填步骤且截图保存完成后，进入 awaiting_review。
用户确认正确后记 simulated_success，展示“模拟提交成功（未实际提交；平台受理未验证）”。
截图失败、字段不符、未完成必填步骤或用户未审核，不得生成模拟成功。
截图及审核绑定 taskId、资料快照、计划修订与采集时间；修改资料使旧审核失效。
证据保存后可关闭云会话，人工审核已保存截图不要求浏览器继续运行。

dry_run 可生成准备轨迹和适配候选，不计真实受监督成功，不写真实提交尝试，不占用已受理去重记录。
它不能证明平台会接受：提交时触发的税号、邮箱、条件必填、验证码、服务端校验及受理结果均可能未覆盖。
此限制出现在结果页、验收记录和汇总，不能把 A0 通过解释为提交风险已低。
填写可能触发联想或草稿保存；记录已观察副作用，不保证所有站点允许无限次 dry_run。

## 2. 架构与路径分流

~~~text
本地 React 页面 -> Node.js 控制器 -> 二维码 / 入口规则 / 资料快照
                                      |
                   +------------------+------------------+
                   |                                     |
          匹配已审核适配器 / 同任务轨迹               未知或步骤不匹配
             程序准备、填写、校验                    Harness 辅助理解
                   +------------------+------------------+
                                      |
                        共用浏览器、状态与提交控制器
                                      |
                             Lexmount -> 商家页面
~~~

已知路径及完全匹配的回放不创建 Harness、不调用模型；模型不可用不阻断它们。
未知路径按需启动运行时，关闭通用 shell、任意文件读写和脚本执行；模型只获受控工具及 valueRef。
程序持有真实资料和服务凭据。插件使用任务绑定的运行期令牌，无改适配器/批准/启用工具。
不用独立适配器管理 API、管理令牌或发布状态服务。

1. 上传创建 inputId；用户选择资料、模式并开始，服务校验后返回 taskId / HTTP 202。
2. 解析入口、去重、核对商家与交易，选择引擎及适配器；运行期间固定配置和资料快照。
3. 匹配则程序执行；不匹配保留已验证进度，只把差异交 Agent，不反复从头探索。
4. dry_run 填写后等待截图审核；read_only 返回事实。execute 的权限见第 7、8 节。
5. 保存结构化结果、轨迹和截图，关闭运行时/会话；模型自然语言不能代替任务结果。

V1 只有一个运行任务，data/ 使用单实例锁；取消在每步及提交前检查，清理资源后释放执行槽。
没有后台自动重启任务或自动放宽预算；模型空闲、进程退出都不代表成功。

## 3. 资料与持久化

三个视图是“提交开票”“开票资料”“任务记录”。上传、保存资料和刷新不提交。
基础字段为购买方类型、完整抬头、收票邮箱；企业计划需有效税号，个人不沿用企业税号。
发票类别独立于购买方类型；地址、电话、银行及手机号按页面条件收集，其他时候不发送。
可保存不完整草稿，但不能启动缺基础项的任务。缺税号可待查询，准备完成前必须补齐。

税号优先级：用户手填 > 与当前完整名称绑定的已确认查询值 > 本次可靠查询/商家联想。
手填值错误或被拒绝时提示核对，不静默替换。联想改写后回读，无法保留手填值则提示冲突。
查询只自动接受唯一完整名称精确匹配；多候选、简称、分支机构交用户选择。
名称变化使旧查询值失效；异步旧响应不能覆盖新名称或手填。任务补齐不自动改长期资料。
v0.3 资料页以独立 Harness 工具集检索公开网页并核对正文，返回公司名称/税号候选及来源，用户选择后保存。
模型不能从记忆或摘要直接填税号；正文同时支持名称/代码且代码校验通过才入选，来源受限则返回空结果。
首版公共查询限 18 位统一社会信用代码；商业查询 API 保留后续接入。模拟提供方只用于本地测试。
未配置查询时提示手填，合成公司数据不得流入真实商家填写计划。

| 位置 | 内容 |
| --- | --- |
| src/adapters/<完整域名>/ | Git 审核的流程 JSON 和填写审核配置，运行时读取 |
| src/rules/ | 通用规则加载、契约校验、工具执行与候选生成 |
| tests/fixtures/ | 合成/脱敏网页、响应及二维码；自动化输出在 test-results/ |
| data/invoice.sqlite | profiles、inputs、tasks、confirmations、submission_attempts |
| data/samples/、data/uploads/ | 真实测试原图/案例索引、应用上传图片 |
| data/artifacts/<taskId>/ | pre-submit-<stepId>.png、字段回读、轨迹、结果证据 |
| data/adapters/ | 待审核草稿、离线报告、私有受监督证据；无生命周期表 |
| data/logs/、data/tmp/、data/harness/ | 脱敏诊断、临时文件、运行时目录 |

既有云端观察保留在 data/lexmount-observations/，旧截图在 data/artifacts/legacy/。
目录按模块位置定位项目根，INVOICE_AGENT_DATA_DIR 可覆盖；相对覆盖仍相对于项目根。
v0.1 启动时创建 SQLite，当前 profiles/inputs/tasks 已实现，审核随任务保存。普通 SQLite/文件无应用加密；备份前停止服务。
data/ 不作静态目录，用户经本地受控接口查看证据。公开构建只包含前端产物。

任务保存资料快照、mode、executionSource、submitPolicy、配置修订、交易/入口别名、状态和结果。
运行期间编辑默认资料不改变本单；明确更新快照后重新填写/校验/截图。
清理截图仍保留真实成功或不确定交易的最小去重记录，避免清理历史后重复申请。

## 4. 入口、引擎与人工操作

### 4.1 二维码和入口规则

二维码直接用 zxing-cpp 限定 QR 格式；失败再定位、裁切、透视及有限预处理。
t3 固定结构修复保留为显式诊断分支，不猜数据格；多码让用户选择，无可靠值提示原图/完整 URL。
URL 解析后匹配精确 host/path，入口仅允许网页协议，拒绝本机、内网、文件及客户端协议。

| 规则/页面事实 | status / reasonCode | 依据 |
| --- | --- | --- |
| kiwa-tech.com 或 www.kiwa-tech.com，路径以 /scanIOrder 开始 | unsupported_browser / known_client_entry | t1 用户确认，记录来源和日期；不是从 404 推导 |
| 主页面实际导航到 open.weixin.qq.com/connect/oauth2/authorize | unsupported_browser / wechat_oauth_required | 微信网页授权入口规则；不依赖错误页文字 |
| 页面明确要求客户端 | unsupported_browser / client_required | 当前页面的文字证据 |
| 当前已有申请/已开票 | already_submitted / already_issued | 当前交易状态，停止新申请 |
| 明确失效/一般 404/网络或渲染失败 | failed / 对应原因 | expired、invalid_link、access_error、network_error 等 |

微信规则仅匹配 HTTPS、默认端口、精确主机及路径，来自本任务主 frame 导航/重定向。
保留 ruleId、source=redirect_rule 和跳转证据；不匹配文本链接、子 frame、近似域名或 /connect/qrconnect。
若实际已完成授权并回到可用表单，按当前业务状态继续，不因历史经过授权地址强制失败。
t6 2026-10-15 light 证据是上述授权地址加通用错误 Oops! Something went wrong:(，
不冒称重现旧的“请在微信客户端打开”。相同地址在两引擎下分类相同，不要求最终地址一定相同。
关闭规则后按实际页面判断；通用错误本身不能证明 client_required。

### 4.2 引擎、观察和定位

2026-10-15 记录显示 t2 提交按钮 DOM 矩形为零，t2/t3/t4 的 innerText 有遗漏，t5 light 截图重叠。
这些事实说明读取信号存在不一致，尚未证明 t2 的正常 fill 必然失败。
观察分别保存 innerText、去脚本 textContent、标签/role、矩形、CSS 状态和截图，标明来源/引擎。
textContent 可能含隐藏内容，截图可见也不保证正常 click/fill 可用；冲突记 unknown，不擅自判可操作。
targetContract 使用当前引擎的正常动作与回读证据，不能只看一份 DOM 或模型置信度。
不使用 force 点击、改 CSS 或直接赋 DOM 值冒充正常填写成功。

先完成资料页和最小任务流程，再用同一资料快照在 t2 做 light/normal 独立 dry_run 对照：
记录正常 fill/必要安全点击、blur 后值、联想候选、必填项、截图、错误、逐步耗时和资源关闭。
每次先查当前交易能否填写，停止于提交前；未知草稿/锁单副作用先查清，不能假定第二次一定可填。
网络被阻断的合成诊断不能替代该业务对照；不得按本地模拟耗时编造模型/云端时延。

引擎选择优先使用已实测配置：light 正常填写失败且 normal 成功，则该表单流程直接默认 normal，
同流程新商户复用，不让每单先失败一次。共同原因另判网络、业务或认证失败。
其他未经验证的完整表单暂用 normal；light 用于只读/对照和已证实兼容的表单。
这是待验证的工程默认值，不是 normal 在所有站点已通过的结论；不把单页差异扩大到整个平台。
切换引擎重新核对原交易、回放准备、回读/截图并废弃旧元素和确认；提交后只许查结果。

### 4.3 人工接管

SDK 0.6.1 有 session.inspectUrl 和 sessions.listTargets() 的 target.inspectUrl。
session.inspectUrl 可能是 SDK 拼接的后备地址，字段存在不等于能打开实时画面或输入。
当前已核对官方能力文档/安装包声明，尚未验证控制台登录、有效画面、鼠标键盘及两引擎差异。
接入第 1 步用可控测试页实测：获取链接、打开相同会话、看画面、人工输入/拖动、程序回读和关闭。
若 normal 支持而 light 不支持，需人工操作的流程直接用 normal；不可用则明确提示能力缺口。

短信验证码在本地任务页提供一次性输入框，由控制器填入原站；值不进模型、日志或长期资料。
发送短信可能产生副作用，不自动反复发送；t2 短信套餐提示不等于必有验证码，按当前控件判断。
滑块/图形操作通过经过验证的人工通道处理，暂停 Agent 与自动操作，显示会话剩余时间及“继续”。
恢复后重新观察、核对字段/交易/签名并生成新预览；人工改业务字段需留痕，不能冒充确定性执行。
dry_run 人工通道也必须能限制真实提交；普通 DevTools 链接不能提供这种保证。
未验证该限制前不把真实 dry_run 页面交给无限制接管；返回 needs_user_input，记录未完成验证。
无可用通道时保留证据和阻塞原因，不承诺静态截图可以操作远程浏览器，不自动破解验证码。

## 5. 字段识别、轨迹和预算

### 5.1 一步循环

1. 观察页面类型、购买方/销售方区域、字段语义、必填/禁用状态、frame、交易及错误。
2. Agent 提出字段映射、一步动作及预期结果；控制器核对当前元素、资料和模式。
3. 程序按 valueRef 填值、回读，处理企业联想、类型切换和明确不创建申请的表单步骤。
4. 比较前后状态，新增字段、协议、票种或目标歧义时停止自动路径，保留进度。
5. dry_run 抵达真实提交前就截图待审核；未来 execute 才按第 8 节确认和提交。

标签结合表单区域、关联 label、role/name、提示文字及稳定属性；不得把销售方公司当购买方。
联想选择后重新回读公司、税号等联动字段；输入搜索词不等于已选择有效抬头。
每次页面更换作废 elementRef。确定性操作记录 modelCalls=0，不为正常成功额外调用模型总结。

### 5.2 持久轨迹

| 字段 | 内容 |
| --- | --- |
| scope | frame、表单/区域及 shadow host 的稳定定位 |
| locatorCandidates | 有序 label、role/name、稳定属性及短 CSS；记录唯一性 |
| targetContract | 标签/type/区域、匹配数、引擎与动作可用性证据；冲突标 unknown |
| beforeState / afterState | 页面阶段、必填集合、协议/票种、当前资料值的断言 |
| action | fill/select/navigate、valueRef、动作效果及已知副作用 |
| replayPolicy | prepare_only / needs_confirmation / never |
| evidenceRefs | 前后观察、截图、回读、请求摘要、stepId 和时间 |

稳定定位由工具采集；动态 id、长 nth-child、当前 token 不能直接升为可复用规则。
订单、商户身份、金额和资料是任务数据，规则只引用参数，不把首个案例实际值写进模板。
同名字段先限区域/frame；多匹配或候选定位到不同元素时不任取第一项。
草稿由服务导出到 data/adapters/，模型不能写入生效的 src/adapters/。
仅有截图没有定位/状态契约的记录是不完整轨迹，不能声称已有可回放适配器。

重新准备依次使用有效会话、本任务轨迹、Agent 补齐差异。先查提交记录，成功/已有记录停止，
submitting/outcome_unknown 只查结果。回放只走 prepare_only，重新获得会话值并回读。
不重放旧确认、提交、协议、补发或有歧义下一步；确认过一次不代表以后会话都能执行。
最后生成当前截图/预览；恢复同任务不自动获得 automatic 权限。
跨新交易使用已审核流程配置，不能复制旧任务请求、token、订单或确认。

### 5.3 探索预算

删除固定的“24 轮配 180 秒”组合。分开配置 maxModelTurns、activeTimeoutMs、
每个导航/动作/模型调用超时；记录 observeMs、modelMs、actionMs、readbackMs、screenshotMs。
会话创建/连接、业务主动处理、人工等待分别计时；人工等待不耗模型轮数，但仍有会话保留期限。
接入阶段暂用 24 轮/15 分钟主动处理上限，单动作 15 秒、导航 45 秒、模型调用 90 秒，
均为可调整诊断值，不是性能承诺。任一限制到达即停，不自动重置或继续后台循环。
同一状态+动作连续两次无进展提前停止；正在提交则转结果查询，不能按探索重试。

t2 对照后按完整轮次计算耗时；样本够才报告 P50/P95，单次只报样本数、实际值和范围。
建议主动预算按轮数 × 完整轮次 P95 × 1.5 估算，再受操作者配置的成本上限约束。
纯适配器对照没有模型调用，只能估浏览器部分；需追加未知页实际模型轮次才能定模型预算。
固定参数及依据写入配置和验证报告，后续新证据才调整。

## 6. 自动范围：流程变体＋参数签名

范围为 platformId + flowVariantId + parameterSignature，绑定执行配置修订，不默认绑定商户 ID。
platformId 来自已知入口/流程识别；域名或相似 DOM 只用来找候选，不能单独作为自动依据。
flowVariant 表示步骤图、字段语义/条件、申请动作及结果规则一致的一类流程。

参数签名包括购买方类型/票种、条件必填与可选字段开关、协议正文哈希、步骤及验证分支，
以及影响流程的商家配置，例如需要短信验证码的开关。按已声明的规范化规则计算。
协议只能去无意义空白等已审核差异，不能抹去商家条款；取不到正文或参数未知就不匹配。
订单号、金额、商户 ID、抬头、税号、时间和 token 不进入此自动范围签名。
商户 ID 仍保存到当前任务，用于核对目标、交易关联、去重和错误排查。

新商户参数签名命中已验证组合，且当前步骤契约完整匹配，就直接复用自动范围。
无需为这家店再做一次采样或真实受监督提交；同平台新参数组合才退回确认/辅助。
在每个关键步骤和提交前重查签名、当前交易及回读，新增必填项、协议或步骤则停止自动执行。
多个适配器不能唯一匹配时交辅助。例：A/B 店同签名共用，C 店增加验证码则退出原范围。
引擎偏好随流程变体和已验证参数组合复用，不随商户 ID 重学。

## 7. dry_run 采样、一次真实验证与 Git 管理

### 7.1 最少真实提交数量

顺序：dry_run 探索采集准备轨迹 -> 人工审核草稿/离线验证 -> 一次真实受监督提交
-> 开发者明确启用。前半段当前可做，真实验证和启用留待用户后续开放。
默认 N=1 笔真实明确成功；可调高，不可设 0。同一未消耗链接可先采样再用于这次提交，
无需两笔独立可申请订单；复用前查明仍未申请、未锁定且资料/步骤匹配。

该次真实提交从头由固定适配器准备和填写，用户确认，控制器提交并读取结果。
不沿用 Agent 留在页面上的值作为“适配器填写通过”，应重新建立准备过程并回读。
结果可调用共用的确定性通用判读器，无需先消费一单获取成功截图：本次动作后的明确受理事实、
同交易关联和会话/页面或响应证据必须一致；没有足够事实则 outcome_unknown。
通用判读器属于受版本约束的执行代码，不要求结果文案预先按该商户注册。

受监督证据含流程/签名、执行规则与执行器修订、引擎、计划、回读、确认、attempt 和原站结果。
填写及结果判读 modelCalls=0，未被人工改业务字段或模型接管，才计入启用证据。
仅人工处理验证码单独记录，自动范围必须声明该暂停分支，不能报成全程无人操作。
模型兜底解释可帮助完成本单，但不计确定性自动证据；修规则后仍缺真实证据要如实记录。
一笔是最小需求，不承诺遇到页面变化、业务拒绝或不明结果时仍能一笔完成。
重复查询/回放同交易不重复计数，模拟成功绝不算真实成功。

### 7.2 简单配置和审核

~~~text
src/adapters/<完整域名>/flow.json 网站入口、流程变体、控件语义、逐步契约与动作
src/adapters/<完整域名>/policy.json 填写审核、enabled=false、未来真实证据引用
src/rules/                       通用加载/校验/执行和候选导出
data/adapters/candidates/<taskId>.json 域名候选，仍需人工审核，不自动发布
tools/check-adapters.mjs          单一只读检查脚本（已实现填写配置检查，真实证据门槛待接入）
~~~

开发者用 git diff 审核，Git 提交记录说明和版本。当前填写复用使用绑定 flow 内容的 preparationReviews，enabled 必须为 false；真实提交启用留待后续用户另行开放。
不建 candidate/validated/supervised/enabled/disabled 生命周期，不建 adapter_releases 表，
不建七个管理命令、管理令牌或管理服务。停用即 enabled=false，准备草稿始终不生效。
应用 Agent 无写文件和启用能力；配置文件或网页里的模型指令不能获得这些能力。

运行时每任务重新读取 JSON，不需要重启或重新部署，也不依赖 Git 命令。flow 内容摘要绑定填写审核，实际 flow/policy 文件摘要用于运行期变更检测，任务保存实际加载副本；这些摘要不是新的发布状态系统。
改定位/动作/协议/范围/引擎使旧 flow 审核不匹配；撤销审核、删除或修改规则在下一动作前停止。新增网站不新增 fillA()，通用工具缺少新能力才需要改代码。
后续真实受监督证据仍须绑定通用执行器/控制器/判读器版本；当前未实现该证据校验，不能用 JSON 审核替代真实验收。

当前检查脚本与服务共用 JSON/动作/范围和填写审核匹配校验，只报告结构及审核数量，不修改配置。真实 enabled=true 直接拒绝；最少一笔真实成功校验和后续提交前证据复核尚待实现。
enabled=false 的完整已审核准备规则仅可复用 dry_run，候选永不自动启用；截图确认不改变规则审核状态。发现变更在下一动作前停止并重新准备。

随应用分发 flow/policy、脱敏 fixture 和绑定修订的验证摘要，不分发私有资料、令牌、截图或绝对路径。
已验证同签名可跨商户和安装复用，不要求接收者每家店重验；未验证组合仍走辅助/受监督。
发布摘要由开发者构建加入，不从网页或模型接收；本地模式关闭真实提交时发布 enabled 无效。
当前工作区已初始化本地 Git，尚未提交；正式规则集合为空。通用回放的合成回归不代表真实商家已验证，也不宣称已可真实启用。

## 8. 确认、去重与真实提交（后续阶段）

### 8.1 去重键与关联

| 层级 | 键 | 用途及限制 |
| --- | --- | --- |
| 请求 | 客户端幂等键 | 双击/HTTP 重试返回同一任务 |
| 输入 | 原图 SHA-256、原始二维码/URL 字节摘要 | 相同图/入口检测；保留查询参数、顺序、编码、fragment，不任意去 token |
| 交易 | 平台＋商户/命名空间＋稳定交易 ID，或已验证一次性入口 token | 同交易不同图/入口别名合并；商户内订单号不是平台全局唯一 |
| 缺交易标识 | 精确原始入口摘要 | 只保证这个入口不重提，不能证明不同链接不是同一交易 |

由已核对的平台解析规则确认 token 的交易含义，不猜参数名或把临时跳转 token 当稳定 ID。
图片重拍但 QR 相同仍命中入口摘要；发现强交易键后，所有旧入口作为别名保留并原子关联。
金额/商户/时间/抬头相近仅显示疑似重复，不用模糊组合自动合并不同订单。
缺可靠交易/token 标识时降低去重置信度、禁止无人确认真实提交；无本地成功/不确定记录时，
可展示入口、商家、金额及重复风险供用户确认后受监督办理。无足够事实核对本单则停下。
同入口已成功/不确定不能靠再确认清除；只读查结果。不同入口缺关联时明确跨链接去重有缺口。

真实提交前事务内保留交易键和全部入口别名、写 attempt；同一有效键只允许一个运行/成功/不明尝试。
多个任务后来解析成同交易时选定一个执行，其余复用结果或提示资料冲突，不各自提交。
dry_run 只做请求幂等和任务内防重，不占用真实申请键；再次测试仍查商家当前状态。

### 8.2 预览与一次提交

execute 下，签名匹配且已启用/证据充分的适配器可自动；其余已准备任务等用户确认。
预览含当前截图、商家/交易/金额/票种、预期与实际字段对照、协议及将执行按钮。
confirmationId 绑定任务、交易或入口、资料/计划修订、页面状态、目标及协议，过期/已消费不可复用。
修改字段、切换会话/引擎、结构变化均作废；中间动作确认不自动授权最终提交。

1. 核对模式、签名、Git 修订/启用/证据、去重记录、回读、按钮唯一性及取消标记。
2. 原子写 attemptId 并消费有效确认，置 submitting；每次尝试最多执行一次批准动作。
3. 保存前后证据，读明确受理/拒绝事实。异常或结果不明置 outcome_unknown，只读查询。
4. 只有明确证明仅推进页面且未申请，才记 advanced_without_submission，再准备新确认。
5. 平台明确拒绝且未创建申请才可修正重试，新计划/新确认/新 attempt，保留历史。

后续真实成功标准是申请获页面明确确认，不核验邮箱到账或下载发票。
旧截图有“成功”、模型高置信或页面跳转本身均不能代替同交易本次受理证据。

## 9. 状态、恢复和下一阶段

| status | 含义 |
| --- | --- |
| running | 解码、观察、填写、回读等 phase |
| needs_user_input / needs_adapter | 缺资料/验证码/可靠操作能力，附 nextAction |
| awaiting_review / simulated_success | 当前 dry_run 待审核/仅本地模拟成功 |
| awaiting_confirmation / submitting | 后续 execute 待确认/已登记一次真实动作 |
| submitted_success / already_submitted / already_issued | 本次明确受理/已有申请/已开票 |
| outcome_unknown | 可能已申请，只允许查结果 |
| unsupported_browser / failed | 客户端入口限制/具体失败 reasonCode |
| cancelled / interrupted | 仅在确定未申请时表示取消/执行中断 |

结果包含模式、事实、证据、资料摘要、engineUsed、modelCalls、executionSource、simulation、
actualSubmitted 和 nextAction。金额用十进制字符串，敏感值只在私有证据保存。
界面用结构化结果生成文案，每 2 秒轮询，终态停止；刷新仅查询，不重新执行动作。
待审核/待确认在横幅、列表及标签页标题持续提示，重新打开从数据库恢复。

真实确认/人工操作会话默认保留最多 5 分钟，可取消释放；等待时关闭模型运行时。
超时保留任务但废弃旧确认，回来优先回放并生成新预览；截图审核不受该会话期限影响。
重启时 submitting 保持不确定，其他执行中任务为 interrupted，旧确认失效。
关闭应用页不承诺系统推送；后台轮询延迟不改变服务端提交幂等性。

V1.1 批量复用 runTask，资料/计划/结果独立，默认串行；未知项保存证据后让出执行槽。
暂停不再领取新项，当前项按已执行状态收尾；全局凭据/额度错误暂停整批，单项错误不阻断其他项。
汇总区分模拟成功、真实成功、已有记录、待人工、失败和不确定，不把处理结束写成全部成功。
真实企业查询与批量独立交付，采购等待不阻塞批量。

## 10. 本地保护、运行与依据

单用户可信电脑：服务只监听回环，校验 Host/Origin 和同源写请求；无账号/角色管理系统。
.env 后端读取，进程环境优先，页面只显示配置是否存在。Agent 环境按需提供，不暴露浏览器凭据。
网页内容是数据，不扩大工具权限；资料只向所选商家及必要查询服务发送，模型默认接脱敏观察。
上传限大小/类型，文件路径受限，data/、.env、诊断和私有案例不发布。
会话创建超时先核查已知 session；关闭连接后关闭并确认会话状态，finally 关闭客户端。
默认关闭无关下载/录制，不自动开启验证码破解；原始资料/截图普通文件保存，后续再考虑加密。
源码验证 Windows x64、macOS ARM64、Ubuntu x64；Python 子进程用参数数组和可配置解释器。
