## 1. 当前阶段

已完成二维码工具/6 项测试、2026-10-15 云端只读观察和目录整理。
v0.3 已实现资料页、任务/SQLite、规则路径及 Harness 真实模型工具循环、公开网页公司税号查询，边界见 [实现记录](IMPLEMENTATION_STATUS.md)。
本地多步模型填写已实测，真实商家填写、跨会话规则晋升与人工接管仍未完成；历史证据见 [观察报告](LEXMOUNT_OBSERVATIONS.md)。

本阶段只做 read_only 或 dry_run，真实提交关闭。用户在“开票资料”页保存资料，
任务选择已有资料后填写、回读、截图，用户审核后反馈“模拟提交成功（未实际提交；平台受理未验证）”。
不在开发对话中要求用户提供资料；t2 引擎对照等资料页及最小填写流程做好后再执行。
模拟成功只证明已完成的填写和人工核对，提交时及服务端校验未覆盖；A0 通过不代表真实提交风险已低。

## 2. 本轮决策

| 问题 | v3.4 决策 |
| --- | --- |
| 每家店重新验证难以复用 | 自动范围改为平台内流程变体＋参数签名，同签名新商户直接复用；商户 ID 用于核对和去重 |
| 首单消耗真实链接 | dry_run 生成候选，离线验证后只需一笔真实受监督成功，默认 N=1；可用同一尚未消耗的链接 |
| 引擎信号不一致 | 资料页和最小流程完成后做 t2 双引擎对照；失败流程直接选已验证引擎，不每单重复失败 |
| 管理过重 | 流程 JSON＋policy JSON＋Git＋单一检查脚本；取消发布表、状态机、管理令牌和管理命令集 |
| 缺人工通道 | 第一阶段核验 inspectUrl 实际画面/输入能力；短信输入和滑块接管明确暂停、恢复和超时 |
| 预算及去重缺项 | 分开记录完整轮次耗时并调参；补原始入口摘要/强交易键/别名关联及无 ID 的受监督降级 |

## 3. 首版需求

| 编号 | 必须交付 |
| --- | --- |
| R1 任务入口 | 单图上传/完整 URL、选择资料、开始；模式区分只读和填写测试 |
| R2 资料管理 | 企业/个人多抬头和默认项、草稿/缺项提示、资料快照；保留已上传图片 |
| R3 税号规则 | 手填优先，联想后回读，缺税号不能完成企业计划；模拟查询只用于本地测试 |
| R4 自动复用 | 按流程变体＋参数签名命中已验证配置，新商户不增加门槛，正常路径零模型调用 |
| R5 入口/状态 | 已申请/已开票、明确失效、普通访问错误、已知客户端入口分别判断 |
| R6 首单与配置 | dry_run 采样、稳定准备轨迹、同任务回放；Git 人工审核和单一证据检查 |
| R7 人工与恢复 | 截图审核、验证码/接管、持续待办提示、超时恢复、去重及提交未知只查结果 |
| R8 本地运行 | 三系统源码运行、数据定位不随工作目录变化，凭据不进入前端/日志 |

普通用户只用“提交开票”“开票资料”“任务记录”。上传和保存本身不提交。
基础资料为购买方类型、抬头、邮箱；企业需税号，电话/地址/银行等按实际条件填写。
资料页已有模型公共网页公司查询，正文来源核对后展示候选，由用户点选；手填仍可用。商业 API 查询保留后续。

当前所有适配器只测试。未来 execute 开放后，enabled 且签名/版本/证据匹配者可自动；
未启用的已审核配置受监督执行，未知或参数变化交 Agent/用户确认。
签名覆盖票种、必填/可选开关、协议正文和步骤/验证分支，关键步骤及提交前再次核对。
取不到必要配置或出现新内容时退出自动流程；不得把相同平台域名当作全部配置已经通过。

## 4. 验证与轻量审核

dry_run 探索生成准备草稿，经 Git diff 人工审核和离线验证后，固定适配器执行一笔真实订单：
重新准备/填写 -> 用户确认 -> 一次提交 -> 共用确定性结果判读器读取明确受理证据。
默认 N=1；这次可以是同一链接的第一次真实提交，无需另消费首单。业务失败可能需要补验证。
模拟结果、同一单重查、模型/人工修业务流程的成功不计确定性真实证据。
规则可在第一单使用通用受理判读，不要求先收集该店成功截图；事实不明就保留 outcome_unknown。

src/adapters/<完整域名>/flow.json 放流程变体和结构化步骤，policy.json 放填写审核与真实提交边界，Git 记录人工审核和版本。通用实现位于 src/rules/，规则增删改不要求重新部署或重启。
data/adapters/ 仅保存草稿/私有证据；tools/check-adapters.mjs 已有填写配置检查，真实证据校验仍待实现。
当前填写复用由开发者完成完整契约审核并绑定 flow 内容，检查通过不自动批准；运行服务核验逐步契约和磁盘变更。真实 enabled 必须为 false，真实证据校验留待后续。
流程与审核配置分开；运行任务保存实际加载副本，不静默切换新版。模型无写文件/启用工具。
分发时随应用带规则、脱敏样本和验证摘要，同签名新商户直接复用，无私有资料或自动遥测。

## 5. 实施顺序

1. 接入及本地骨架：核验 Harness 调用/关闭、Lexmount normal/light 连接和资源关闭；
   在可控页验证 inspectUrl 的实时画面、输入/拖动、授权与过期，不把有链接当作能接管。
2. 资料页和任务快照：用户自行保存抬头/税号/邮箱，完成 QR、入口规则、持久化与本地模拟流程。
3. 最小 dry_run：选择已保存资料，在 t2 分别用 light/normal 正常填写、回读、截图，不提交。
   记录状态差异、逐步耗时、完整轮次；没有模型调用的测试不用于推断模型时延。
   根据证据确定表单引擎；有可靠结论的流程直接选该引擎。当前未经验证的完整表单暂用 normal。
4. 完成多步辅助、轨迹回放、人工审核、接管/验证码、签名范围、Git 检查与异常恢复。
   当前 A0 和离线分支通过后由用户核对；不为 A4 消耗真实链接。
5. 用户完成验证并明确开放真实执行后，每范围最少一笔受监督真实提交，验证结果/去重并人工启用。
6. V1.1 增加串行批量和真实公司查询；两项独立交付。

若 t2 当时失效或已申请，保留事实并换可用交易，不能强行复用或把历史表单当作当前页面。
缺资料由应用提示用户完善，不以聊天提供或合成数据代替正式资料流程。
首次接入阶段结束给出通过项、阻塞项和剩余工期；人工通道不可用等问题应具体列出。

## 6. 范围与成本

本地 Node 服务提供 React、API、SQLite 和单任务执行器；已知程序路径与未知 Harness 路径共用控制器。
normal/light 的读取和动作按实测选择，配置随流程签名跨商户复用；未知路径模型按需启动。
探索诊断预算暂为 24 轮/15 分钟主动时间，按完整轮次分项实测再定，不再固定 180 秒。
人工等待单独计时并有会话保留期限；两次无进展或到预算即停，不自行重启。

V1 本机单用户、源码运行；V1.1 批量和查询。暂不做小程序/手机自动化、自动破解验证码、
邮箱到账、下载归档、红冲重开、并发队列、多用户、公网部署、远程审核或适配器市场。
资料为本机普通 SQLite/文件，必要填写仍经云浏览器发给商家；加密、导出和桌面包后续按需。
