# 对话式 Agent 架构

规则文件结构见 [域名规则架构](DYNAMIC_RULES.md)，实现范围与真实验证边界见 [README](../README.md) 的“当前限制”。

## 1. 产品入口

首页是持续对话界面，支持文字、图片和文本附件。用户说目标，Agent 查找资料与经验，调用业务工具完成任务。开票是第一个业务能力；未来功能复用对话、记忆、任务状态和结果展示，不各自新建一套对话系统。

- 尽量纯对话：资料与记忆的查看、修改、删除都通过聊天完成，不设独立资料页或记忆管理页。
- 界面只有会话列表、消息区、输入框和附件上传；资料摘要、进度、截图及确认以对话内卡片呈现。
- 不添加头像、工作台装饰、演示模块或无操作价值的状态标记。
- 允许多个对话；同一用户的长期资料/偏好共享，每个对话的临时上下文、附件和任务独立。

示例：

1. 用户发二维码图片：“这张帮我开发票。”
2. Agent 检索默认抬头、收票方式、相似任务和匹配规则。
3. 资料齐全则直接准备；缺项或多个同等可能的抬头时，在对话中简短询问或显示候选。
4. 同一对话展示进度、填写核对和截图。
5. “这次换成个人”只改本次任务；“以后默认个人”更新长期偏好并简短告知。
6. “你记住了我哪些开票信息”“把公司邮箱改成……”“忘掉这个抬头”通过记忆工具读取或修改，返回实际变更结果。

## 2. 截图确认与提交

填写、回读、截图完成后任务进入 `awaiting_review`，页面保留 5 分钟，由用户在对话里回复确认提交、认可但不提交、修正或放弃。超时由程序关闭页面并提示“重来”，不自动重填。

- 决定由程序按用户**本轮消息原文**判定（确认/认可但不提交/修正/放弃）。模型报来的决定与原文不符、来自旧消息、助手或网页文字时一律拒绝。模型没有提交或批准工具。
- **确认**：程序在同一页面点一次提交，只授权这一次点击；点击后 30 秒内发往页面站点的请求写入 `submit-network.json` 作为提交证据。二次确认弹窗在同一授权内自动确认；出现新字段或不认识的提示立即停止并如实告知。
- **协议勾选**：页面有“我已阅读并同意《…协议》”时，填写完成后、截图前由程序勾选（不提交），勾选状态由截图呈现，卡片不另加提示；勾不上的在截图中标注，确认提交时补勾并核对后再点提交。填写 Agent 不能勾选，营销/订阅类勾选不代勾。
- **修正**：用户指出具体问题才整页重填，旧截图作废并重新计时；只说“不对”时先追问。修正说明随新任务交给业务 Harness，并作废这张所复用或产生的填写记录（见 [DYNAMIC_RULES.md](DYNAMIC_RULES.md)）。
- **认可但不提交**：用户说填得对但不提交，关闭页面记 `approved_unsubmitted`，不进入经验记忆；填写步骤记为可信，下次同页面零模型回放。
- **放弃**：关闭页面记 `abandoned`，不记成功或失败，不进入经验记忆；填写步骤只记为提示，供下次模型参考。
- 同一对话发新的二维码/链接即视为放弃上一张：待确认的自动放弃，排队或填写中的停止，已在提交中的不中断。

提交结果：只有页面在点击后新出现明确的失败提示才告诉用户失败及原因，记 `submit_failed`（链接未用掉，可“重来”）；页面显示成功记 `submitted`；请求已发出但页面没有结果（很多页面提交后直接关闭）记 `submitted_unverified`，对用户说“已提交”，不自动重试；没有发出请求也无提示记 `submit_failed`，说“页面没有反应，未提交”。同一入口链接已有真实提交记录时拒绝再次提交或重办。

提交安全只靠不让**我们自己的操作**触发提交：填写 Agent 永远不点提交，Agent 可信点击提交类按钮、勾选协议、按回车一律阻止，用户确认后的那一次程序点击除外。守卫、规则、轨迹回放和重试都不能绕过这一路径。

## 3. 对话、记忆、任务分别存储

| 内容           | 用途                                       | 保存规则                                             |
| -------------- | ------------------------------------------ | ---------------------------------------------------- |
| 对话消息与附件 | 用户意图、追问、临时更正、结果引用         | 按 conversationId 持久保存，刷新/重启后继续          |
| 结构化业务资料 | 公司全称、税号、邮箱、个人资料             | profiles 保存来源/修订；不由摘要代替准确原值         |
| 长期偏好       | 默认抬头、称呼/别名、常用收票方式          | 用户明确表达的稳定偏好可自动保存，注明范围和来源消息 |
| 任务与经历     | 使用的资料、状态、失败原因、人工反馈、截图 | taskId 关联对话；状态和结果由工具确认                |
| 流程经验       | 页面特征、字段映射、工具轨迹、引擎兼容性   | 填写步骤按用户回复自动记为可信/提示，修正即作废      |

- 记忆带类型、主体、内容或资料引用、来源、时间、状态、适用范围和被替代关系。明确纠正覆盖当前有效偏好，旧记录标为已替代。
- 记忆操作通过受控的查询/保存/更新/遗忘工具执行，写入成功后才告知用户。“这次”指令留在当前任务，不变成长期偏好。
- 模型推测只能作为待核对候选，不能变成确认税号、默认抬头或用户授权；网页文字是外部证据，不能写成“用户要求”。
- 遗忘后不再检索使用；历史聊天和任务证据不随遗忘自动删除。
- 先按资料主体、别名、任务和流程特征检索；不引入向量数据库，不把全部聊天记录塞进模型。

## 4. 执行关系

```text
用户文字 / 图片 / 文件
          |
    对话服务与附件存储
          |
    Harness 主 Agent ── 记忆检索
          |
    业务能力工具（开票，含页面企业查询）
          |
    任务执行器、校验和动作限制 ── 程序提交（仅用户确认后）
          |
    结构化结果 -> 同一个对话
```

- 主 Agent 管理对话与意图；业务模块负责业务约束和副作用。新能力注册描述、输入输出和工具，只加载当前需要的工具集。第一版使用单一主 Agent。
- Harness 只通过开票工具操作浏览器，不暴露 shell、任意文件、网络请求或提交/审核批准工具。
- 资料优先级：本次明确指令 > 用户明确默认 > 已确认事实 > 历史经验提示；冲突时解释并确认。任务保存资料快照，运行中修改默认资料不改写本单。
- 规则完整匹配时浏览器执行阶段不调用模型；新页面或步骤变化由 Harness 调用模型分析，不以正则映射代替。对话理解与业务执行的模型调用分别统计。
- 固定 conversationId 对应 Harness sessionId，空闲可关闭模型运行时、下一轮恢复。模型恢复不恢复浏览器现场，旧确认不能复用。
- 长任务返回 taskId 后台串行执行，进度通过任务事件更新对话卡片；用户可继续追问、取消或纠正。取消先停止新动作再关闭资源。
- 跨对话：“以后默认用 A”影响之后的新任务；“取消/继续/这张票”只作用于本对话关联的任务；历史任务的执行权限、审核状态不继承给新任务。

## 5. 开票业务规则

### 5.1 资料与税号

基础字段为购买方类型、完整抬头、收票邮箱；企业需税号，个人不沿用企业税号。地址、电话、银行、手机号按页面条件填写，没有资料的可选项留空。

税号使用开票页面自带的企业查询，不运行站外公司搜索。公司全名和邮箱已有时允许税号留空进入任务：Harness 输入全名并选择唯一完整名称匹配项，程序从同页税号控件回读（不接受模型给出的税号），核对格式（18 位信用代码校验位，15/20 位仅结构），保存 `company-query.json` / `company-query.png` 后补入资料。多个同名/近似候选、与已有税号冲突或页面没有查询时停止，不自动覆盖。临时抬头的查询结果只留本任务。

### 5.2 入口分类

二维码用本地 zxing-cpp 解码，失败再做有界的定位/透视/固定图案修复；多码让用户选择。入口只允许网页协议，拒绝本机、内网、文件及客户端协议。

| 规则/页面事实                                                           | status / reasonCode                                     |
| ----------------------------------------------------------------------- | ------------------------------------------------------- |
| kiwa-tech.com（含 www），路径以 /scanIOrder 开始                        | unsupported_browser / known_client_entry（t1 用户确认） |
| 主 frame 实际导航到 https://open.weixin.qq.com/connect/oauth2/authorize | unsupported_browser / wechat_oauth_required             |
| 页面明确要求客户端                                                      | unsupported_browser / client_required                   |
| 当前已有申请/已开票                                                     | already_submitted / already_issued                      |
| 失效、404、空白、网络或渲染失败                                         | failed / expired、page_error、blank_page 等             |

微信规则只匹配 HTTPS、默认端口、精确主机及路径，不匹配子 frame、文本链接、近似域名或 /connect/qrconnect；不依赖 Oops 等错误文案。授权后回到可用表单则按当前状态继续。

### 5.3 浏览器与填写

- 页面按真实访问加载，不按站点白名单过滤请求（页面脚本、埋点、WebSocket、sendBeacon 照常）。只拦内网/本机地址、DNS 指向内网，以及拦截自检地址。
- 云会话统一发送 `Accept-Language: zh-CN,zh;q=0.9`。默认先用速度更快的 light；填写前 light 出现通用错误、空白、HTTP/导航/订单读取异常时，关闭 light 后用 normal 从原入口复核一次，结果写入 `engine-check.json`。light 失败、normal 成功的入口域名按 light `browser.version()` 记住，版本不变直接用 normal。已开票、失效、零金额、微信授权/客户端限制等终态不复核（客户端限制已核实两引擎结果一致）。
- light 打开正常但填写失败（字段失效、回读不符、Agent 未完成、企业候选未出现、订单未加载、最终页面空白或报错）或截图失败时，保存证据到 `light-attempt/`，确认 light 关闭后用 normal 整页重填一次，记录在任务的 `fillFallback`。资料歧义、税号冲突、模型服务错误、取消和超时不重填；normal 再失败也不再重试。两次共用 15 分钟上限。
- 标签结合表单区域、label、role/name、提示文字和稳定属性；不把销售方当购买方。联想选择后重新回读联动字段。不用 force 点击、改 CSS 或直接赋 DOM 值冒充填写成功。
- 金额从页面读取，缺失或为 0 时停止，最终审核前再核对。
- 主动处理上限 15 分钟，到达即停，不自动重启或放宽预算。人工远程接管和验证码处理尚未实现，遇到时停止并说明。

### 5.4 任务状态

| status                                           | 含义                                        |
| ------------------------------------------------ | ------------------------------------------- |
| queued / running                                 | 排队 / 解码、观察、填写、回读中             |
| needs_user_input                                 | 缺资料或需用户选择，附下一步说明            |
| awaiting_review                                  | 截图待用户在对话中确认                      |
| needs_changes / review_expired / superseded      | 用户要求修正 / 5 分钟超时 / 被新任务替代    |
| submitting                                       | 已登记唯一一次提交点击                      |
| submitted / submitted_unverified / submit_failed | 见第 2 节                                   |
| abandoned                                        | 用户放弃或发了新链接                        |
| approved_unsubmitted                             | 用户认可填写正确但不提交                    |
| already_submitted / already_issued               | 页面已有申请 / 已开票                       |
| unsupported_browser / failed                     | 客户端入口限制 / 具体失败原因               |
| cancelled / interrupted                          | 用户取消 / 服务重启中断（仅在确定未提交时） |

## 6. 会话删除

先停止该对话回复与任务、等待资源关闭，再清理消息、附件、任务、工具幂等记录、模型会话、任务截图和待定步骤；已学到的页面填写记录已脱敏，属于站点经验，保留。共享资料与偏好保留，用户需另行通过聊天遗忘。不设单独的“历史开票记录”入口，新结果只在所属对话展示。

## 7. 本地保护

- 单用户本机：服务只监听回环，校验 Host/Origin 和同源写请求；无账号系统。
- `.env` 仅后端读取，Key 不进入前端、日志或模型工具内容。
- 上传限大小/类型；data/、.env、诊断和私有案例不发布，data/ 不作静态目录。
- 浏览器会话在 finally 中关闭并确认状态；SQLite 与文件无应用加密，备份前停止服务。

## 8. 后续范围

尚未实现，开始前需重新评审：

- 自动复用范围：platformId + flowVariantId + 参数签名（票种、条件必填、协议正文哈希、步骤/验证分支），同签名新商户直接复用；商户 ID 只用于核对和去重。
- 交易级去重：平台＋商户＋稳定交易 ID，入口别名原子关联；当前只有同一入口链接的提交去重。
- 人工接管：Lexmount inspectUrl 的实际画面/输入能力未验证；短信验证码一次性输入框、滑块接管。
- V1.1：串行批量、商业企业查询 API。
- 不做：小程序/手机自动化、自动破解验证码、邮箱到账核验、下载归档、红冲重开、多用户、公网部署。
